## 1. OBJECTIVE & EXECUTIVE OVERVIEW

Implement a robust, tamper-resistant, high-performance Audit Logging and User 
Activity Tracking Engine for the CafeFlow POS platform.

The system must automatically record an immutable audit trail of user sessions, 
view/tab transitions, administrative actions, financial transactions, and 
security-sensitive events. The interface and underlying data must be strictly 
isolated to users with the `manager` role.

### Core Capabilities:
1. Precise Timestamps: Microsecond-precision (`DATETIME(3)`) event recording 
   calibrated to the store's configured timezone (`Asia/Manila`, UTC+08:00).
2. Tab & View Navigation Tracking: Records every view visit (POS, Sales Reports, 
   Waste Reports, Predictive Analytics, Inventory Modal, Account Management, 
   Security & 2FA), including entry time, exit time, and duration on page.
3. Critical Action Execution Trail: Tracks state-changing actions across the POS 
   (order checkout, cancellation/voiding, inventory adjustments, recipe edits, 
   account status toggling, password resets, and 2FA enrollments/resets).
4. Session Duration & Heartbeat Monitoring: Tracks exact user login timestamps, 
   logout timestamps, active session duration, and idle timeouts using an 
   efficient client heartbeat mechanism.
5. Strict Role-Based Access Control (RBAC): Audit log endpoints, UI views, and 
   exports must be completely inaccessible to the `barista` role (HTTP 403) and 
   exclusive to `manager` accounts.

2. DATABASE ARCHITECTURE (MYSQL / MARIADB SCHEMA)
================================================================================

The audit subsystem consists of two dedicated relational tables:
1. `user_sessions`: Tracks login lifecycles, active duration, IP, and client metadata.
2. `audit_logs`: Append-only chronological trail of system actions and tab visits.

```sql
-- -----------------------------------------------------------------------------
-- Table 1: user_sessions (Session lifecycle & duration tracking)
-- -----------------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `user_sessions` (
    `session_id` VARCHAR(64) NOT NULL PRIMARY KEY,
    `user_id` INT UNSIGNED NULL DEFAULT NULL,
    `ip_address` VARCHAR(45) NOT NULL,
    `user_agent` VARCHAR(255) NOT NULL,
    `auth_method` ENUM('password', 'password_2fa', 'direct_2fa') NOT NULL DEFAULT 'password',
    `login_at` DATETIME(3) NOT NULL,
    `last_heartbeat_at` DATETIME(3) NOT NULL,
    `logout_at` DATETIME(3) NULL DEFAULT NULL,
    `duration_seconds` INT UNSIGNED NOT NULL DEFAULT 0,
    `logout_reason` ENUM('user_logout', 'timeout', 'revoked', 'session_expired') NULL DEFAULT NULL,
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX `idx_sessions_user_login` (`user_id`, `login_at`),
    INDEX `idx_sessions_last_heartbeat` (`last_heartbeat_at`),
    CONSTRAINT `fk_sessions_user` FOREIGN KEY (`user_id`) 
        REFERENCES `users` (`user_id`) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- -----------------------------------------------------------------------------
-- Table 2: audit_logs (Granular activity & action trail)
-- -----------------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `audit_logs` (
    `log_id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `session_id` VARCHAR(64) NULL,
    `user_id` INT UNSIGNED NULL DEFAULT NULL,
    `username_snapshot` VARCHAR(50) NOT NULL,
    `user_role_snapshot` VARCHAR(20) NOT NULL,
    `category` ENUM('navigation', 'pos_order', 'inventory', 'catalog', 'account', 'security', 'system') NOT NULL,
    `action` VARCHAR(64) NOT NULL,
    `description` VARCHAR(255) NOT NULL,
    `target_type` VARCHAR(50) NULL DEFAULT NULL,
    `target_id` VARCHAR(64) NULL DEFAULT NULL,
    `metadata_json` JSON NULL DEFAULT NULL,
    `ip_address` VARCHAR(45) NOT NULL,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    INDEX `idx_audit_created` (`created_at` DESC),
    INDEX `idx_audit_user_created` (`user_id`, `created_at` DESC),
    INDEX `idx_audit_category_created` (`category`, `created_at` DESC),
    INDEX `idx_audit_action` (`action`),
    INDEX `idx_audit_session` (`session_id`),
    CONSTRAINT `fk_audit_user` FOREIGN KEY (`user_id`) 
        REFERENCES `users` (`user_id`) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.1 Central Audit Helper (`core/audit.php`)
Create `core/audit.php` to provide thread-safe, non-blocking logging utilities:

```php
<?php
// core/audit.php
require_once __DIR__ . '/db.php';
require_once __DIR__ . '/auth.php';

function audit_log(
    string $category,
    string $action,
    string $description,
    ?string $targetType = null,
    ?string $targetId = null,
    ?array $metadata = null,
    ?PDO $existingPdo = null
): void {
    try {
        $pdo = $existingPdo ?: db();
        $user = current_user();
        if (!$user) return;

        $userId = (int) $user['user_id'];
        $username = $user['username'] ?? 'unknown';
        $role = $user['role'] ?? 'unknown';
        $sessionId = session_id();
        $ip = $_SERVER['REMOTE_ADDR'] ?? '127.0.0.1';

        // Redact any sensitive passwords or tokens from metadata
        if (is_array($metadata)) {
            unset($metadata['password'], $metadata['confirm_password'], $metadata['secret'], $metadata['recovery_code']);
        }

        $stmt = $pdo->prepare('
            INSERT INTO audit_logs (
                session_id, user_id, username_snapshot, user_role_snapshot,
                category, action, description, target_type, target_id,
                metadata_json, ip_address, created_at
            ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, NOW(3))
        ');
        $stmt->execute([
            $sessionId,
            $userId,
            $username,
            $role,
            $category,
            $action,
            substr($description, 0, 255),
            $targetType,
            $targetId ? (string)$targetId : null,
            $metadata ? json_encode($metadata, JSON_UNESCAPED_SLASHES) : null,
            $ip
        ]);
    } catch (Throwable $e) {
        // Logging failure must never crash core POS operations; log to system error log
        error_log('[CafeFlow Audit Log Failure] ' . $e->getMessage());
    }
}
```

### 4.1.1 Backward-Compatibility Bridge with `security_audit_log`
To prevent regression in existing test suites (e.g., `tools/test_2fa_suite.php`), `log_security_audit()`
in `core/auth.php` remains fully functional: it records into `security_audit_log` and simultaneously
bridges the security event into `audit_log()` (with category `security`), maintaining dual-write consistency.

### 4.2 Session Duration & Heartbeat Tracker (`api/heartbeat.php`)
- In `core/auth.php -> login_user()`:
  * ID regeneration (`session_regenerate_id(true)`) MUST occur BEFORE inserting into `user_sessions`.
  * Create active session record:
    `INSERT INTO user_sessions (session_id, user_id, ip_address, user_agent, auth_method, login_at, last_heartbeat_at, duration_seconds) VALUES (?, ?, ?, ?, ?, NOW(3), NOW(3), 0)`
- Client pings `POST api/heartbeat.php` every 60 seconds (or on `visibilitychange`).
- The server updates `user_sessions`:
  `UPDATE user_sessions SET last_heartbeat_at = NOW(3), duration_seconds = TIMESTAMPDIFF(SECOND, login_at, NOW(3)) WHERE session_id = ?`
- On explicit logout (`core/auth.php` -> `logout_user()`):
  `UPDATE user_sessions SET logout_at = NOW(3), duration_seconds = TIMESTAMPDIFF(SECOND, login_at, NOW(3)), logout_reason = 'user_logout' WHERE session_id = ?`

### 4.3 Manager Audit Log API (`api/audit_api.php`)
- **GET `api/audit_api.php`**
  - Strictly requires `require_role('manager')`.
  - Supports filters:
    * `user_id`: Filter by specific barista or manager.
    * `category`: `navigation`, `pos_order`, `inventory`, `catalog`, `account`, `security`.
    * `date_from`, `date_to`: ISO date range.
    * `search`: Fulltext keyword search against description, username, and target ID.
    * `limit`, `offset`: High-speed pagination.
  - Returns:
    * `logs`: Paginated array of audit items with formatted timestamps.
    * `session_metrics`: Total active sessions today, average session duration, currently online users.
    * `category_breakdown`: Count of actions per category.
- **GET `api/audit_api.php?export=csv`**
  - Generates downloadable CSV audit report formatted for Excel / compliance reporting.

### 5.1 Tab & View Navigation Tracking Hook (`assets/js/modules/navigation.js`)
Hook into `showView(viewName)` with a 2-second minimum dwell-time filter to avoid beacon spam:
```javascript
let currentViewStartTime = Date.now();
let lastActiveView = 'pos';

function trackViewVisit(newView) {
  if (newView === lastActiveView) return;
  const now = Date.now();
  const timeSpentMs = now - currentViewStartTime;

  // Dwell filter: only record views where user dwelled for at least 2 seconds (2000ms)
  if (timeSpentMs >= 2000 && navigator.sendBeacon && window.currentUser && window.currentUser.csrf_token) {
    const payload = JSON.stringify({
      category: 'navigation',
      action: 'tab_view',
      description: `Switched from ${lastActiveView} to ${newView}`,
      metadata: { from_view: lastActiveView, to_view: newView, duration_prev_ms: timeSpentMs },
      csrf_token: window.currentUser.csrf_token
    });
    const blob = new Blob([payload], { type: 'application/json' });
    navigator.sendBeacon('api/audit_beacon.php', blob);
  }

  lastActiveView = newView;
  currentViewStartTime = now;
}
```

### 5.2 Client Heartbeat Timer (`assets/js/core/session.js`)
```javascript
// Ping heartbeat every 60 seconds while window is active
setInterval(() => {
  if (document.visibilityState === 'visible' && currentUser && currentUser.user_id) {
    fetch('api/heartbeat.php', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ csrf_token: currentUser.csrf_token })
    }).catch(() => {});
  }
}, 60000);
```

7. SECURITY, PRIVACY & RETENTION REQUIREMENTS
================================================================================

1. Strict Redaction:
   - PASSWORDS, PASSWORD HASHES, TOTP SECRETS, RECOVERY CODES, AND PAYMENT
     CREDENTIALS MUST NEVER BE RECORDED IN AUDIT LOGS.
2. Immutability:
   - The `audit_logs` table must be strictly APPEND-ONLY.
   - The `api/audit_api.php` file must NOT implement `UPDATE` or `DELETE` endpoints.
   - Even managers cannot alter historical logs.
3. Automated Retention & Archival:
   - Provide a background maintenance script (`tools/cleanup_audit_logs.php`) that 
     archives logs older than 180 days to compressed storage if required.
4. Barista Quarantine:
   - If any user with `role === 'barista'` attempts to call `api/audit_api.php`, 
     the server immediately terminates with HTTP 403 Forbidden and logs a 
     security warning event.
