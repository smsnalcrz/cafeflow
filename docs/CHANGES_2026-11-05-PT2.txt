CafeFlow POS — System Changes & Security Hardening
Release Date: November 05, 2026 | Environment: PHP 8.2 / MariaDB / Apache (XAMPP) | Status: Complete

1. Executive Summary of Implemented Changes
This release eliminates seven critical operational gaps, logic flaws, and access control vulnerabilities across the point-of-sale workflow, order queue, financial reporting, and session management:
• Checkout Underpayment Prevention:Removed silent payment overrides in api/checkout.php. Tendered amounts below order total are strictly rejected (HTTP 422) with exact shortfall calculation.
• Manager-Only Sales Reports & Exports:Enforced server-side RBAC (require_role('manager')) on api/report.php and api/export_excel.php, rejecting unauthorized Barista access with HTTP 403 Forbidden.
• Order Cancellation & Void Workflow:Created api/cancel_order.php. Baristas can cancel Pending orders from the queue; Managers can Void Completed orders with automatic raw inventory restoration. Excluded from active sales totals.
• Inventory Recipe Cascade Protection:Hardened api/inventory_api.php and database foreign key (ON DELETE RESTRICT). Deleting in-use supplies is blocked (HTTP 409 Conflict) with a list of dependent recipes.
• Statutory Discount & VAT Engine:Implemented server-side computation for Philippine Republic Act 9994 / RA 10754 (20% discount on VAT-exempt sales + 0% VAT) requiring ID/Booklet number, plus custom promo discounts.
• GCash Reference Number Enforcement:Mandated 6–30 character reference codes for GCash payments, blocked duplicate reference codes (HTTP 409), and embedded them in transactions, receipts, and Excel reports.
• Server-Enforced Inactivity Timeout:Implemented 30-minute idle session expiration in core/auth.php with HTTP 401 SESSION_EXPIRED API handling and auto-dismissing notice banners on login.php.
